# Chrome Web Store Submission

This document contains copy-ready metadata and reviewer notes for the first public LingoFrame release. Keep every field aligned with the behavior of the submitted package.

## Product details

### Name

LingoFrame

### Summary

Select a webpage region and translate only the readable text inside it with your chosen AI provider.

### Detailed description

LingoFrame gives you a focused way to translate the part of a webpage that matters.

Activate the extension from the toolbar or with `Alt+Shift+L`, point to a content Region, and click to translate. LingoFrame keeps the original content in place and inserts each translation immediately after its corresponding source block, creating an easy-to-read bilingual layout.

LingoFrame is useful for articles, comments, posts, chat messages, table cells, document paragraphs, sidebars, and cards. Scanning stays strictly inside the Region you confirm.

Key features:

- DevTools-style Region Picker with hover highlighting and Escape cancellation.
- Region-bounded readable-text scanning.
- Interleaved source and translated content.
- DeepSeek and OpenAI Chat Completions-compatible providers.
- User-controlled target language, model, endpoint, and API Key.
- On-demand `activeTab` access and optional permission for the configured provider origin.
- API Key storage restricted to trusted extension contexts.

LingoFrame sends only the text from a Region you explicitly select to the provider you configure. It does not operate an intermediary translation server.

## Single purpose

LingoFrame lets the user explicitly select one Region on the current webpage, sends only the readable text inside that Region to the translation provider configured by the user, and displays the returned translations next to their corresponding source content.

## Permission justifications

### `activeTab`

LingoFrame needs temporary access to the current tab only after the user invokes the toolbar action or keyboard shortcut. The access is used to start the Region Picker and operate on the Region the user confirms.

### `scripting`

LingoFrame injects its packaged Region Picker and bilingual presentation content script into the active tab after an explicit user action. It does not inject code automatically on page load and does not download or execute remote code.

### `storage`

LingoFrame stores the selected provider, target language, API Base URL, model name, and API Key in `chrome.storage.local`. Storage access is restricted to trusted extension contexts so page scripts and content scripts cannot read the API Key.

### Optional host permissions

LingoFrame supports DeepSeek and user-configured OpenAI-compatible HTTPS endpoints. When the user saves or tests a provider configuration, the extension requests permission for that exact API Origin. Permission is used only by the trusted background context to test the provider or send a translation request initiated by the user.

The loopback HTTP patterns support model services running locally on `localhost`, `127.0.0.1`, or `[::1]`. Non-loopback provider endpoints must use HTTPS.

## Data-use disclosure

Review the current dashboard categories and disclose at least the following data types because the extension can handle them:

- Website content: readable text inside the Region confirmed by the user.
- Authentication information: the Provider API Key entered by the user.
- Personal communications: possible when the user selects chat or message content.
- User-generated content: possible when the user selects comments, posts, or other authored content.

The data-use certifications should state that LingoFrame:

- uses data only to provide its single-purpose translation feature;
- does not sell or transfer data for unrelated purposes;
- does not use data for advertising, credit decisions, or user profiling;
- does not allow humans to read user data;
- sends selected text and credentials directly to the user-configured Provider;
- does not operate an intermediary translation server;
- stores Provider settings locally until the user changes them, clears storage, or uninstalls the extension.

Keep these statements consistent with `PRIVACY.md` and the disclosure shown in the options page.

## Reviewer test instructions

Provide a temporary, rate-limited API Key in the private reviewer credential field. Never commit reviewer credentials to the repository or include them in the extension package.

1. Install the submitted package and click the LingoFrame toolbar icon. The options page opens because no API Key is configured.
2. Select the Provider specified in the private reviewer notes.
3. Enter the supplied API Base URL, model, and temporary API Key.
4. Keep `Simplified Chinese` as the target language, click `Test connection`, and confirm that `Provider connection succeeded` appears.
5. Click `Save settings` and approve the permission request for the configured Provider Origin.
6. Open a normal HTTP or HTTPS page containing several paragraphs.
7. Click the LingoFrame toolbar icon or press `Alt+Shift+L`.
8. Move the pointer over a content container and confirm that a purple Region outline appears.
9. Click the Region and wait for translations to appear immediately after the corresponding source blocks.
10. Confirm that content outside the selected Region remains unchanged.
11. Activate LingoFrame again and press `Escape`; confirm that the picker closes without changing the page.

Chrome internal pages and the Chrome Web Store cannot be used for this test because Chrome blocks extension script injection on protected pages.

## Release checklist

1. Confirm the version in `package.json` is higher than every previously uploaded package.
2. Merge the release changes into `main` and wait for the `main` CI run to pass.
3. Load `output/chrome-mv3` as an unpacked extension and smoke-test the production build.
4. Create and push the matching `v<version>` tag from the verified `main` commit.
5. Wait for the Release workflow to create the Draft GitHub Release.
6. Download the Chrome ZIP and SHA-256 checksum from that Draft Release.
7. Verify the uploaded manifest name, description, version, permissions, and optional host permissions.
8. Upload the approved icon, screenshots, and promo tile.
9. Complete Store listing, Privacy practices, Distribution, and Test instructions.
10. Upload the Release workflow's Chrome ZIP and submit for review with deferred publishing enabled.
11. Publish the GitHub Release after the Chrome Web Store submission is approved.
